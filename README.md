# Бот для управления задачами прорабов

Telegram-бот на **Python 3.10+ / aiogram 3 / PostgreSQL** + **дашборд для шефа** (Telegram Mini App на React).
Шеф ставит задачи прорабам, бот доставляет их и считает статистику.
Решение «выполнено или нет» всегда принимает шеф.

## Быстрый старт

```bash
python -m venv .venv && source .venv/bin/activate      # Windows: .venv\Scripts\activate
pip install -r requirements.txt
docker compose up -d                                    # PostgreSQL (или свой сервер — см. DATABASE_URL)
cp .env.example .env                                    # заполните BOT_TOKEN, ADMIN_IDS, DATABASE_URL
python -m bot.main
```

1. Создайте бота у [@BotFather](https://t.me/BotFather), токен — в `BOT_TOKEN`.
2. Свой Telegram ID узнайте у [@userinfobot](https://t.me/userinfobot), впишите в `ADMIN_IDS` (можно несколько шефов через запятую — у каждого будут свои прорабы).
3. Запустите бота, откройте его, нажмите `/start` — вы шеф. Таблицы в PostgreSQL создаются автоматически.
4. В меню «👷 Прорабы» скопируйте **ссылку-приглашение** и отправьте прорабам.
5. Прораб переходит по ссылке → шеф подтверждает заявку кнопкой → можно ставить задачи.

Проверка логики без Telegram (нужен любой PostgreSQL — тесты создают и удаляют свою временную схему):

```bash
export TEST_DATABASE_URL=postgresql://foreman:foreman@localhost:5432/foreman
python -m tests.smoke_test       # БД, статистика, миграция, подпись initData, JSON API дашборда
python -m tests.handlers_test    # хендлеры бота через настоящий Dispatcher с подменённой сессией
python -m tests.media_test       # фото и голосовые в дашборде: ссылки, кэш, Range, ogg→m4a, лента задач (нужен ffmpeg)
python -m tests.actions_test     # отметка результата и карточка задачи: права, изоляция шефов, переходы статусов, 409
```

## Дашборд для шефа (Telegram Mini App)

Внутри Telegram открывается веб-приложение с тремя разделами:

- **Обзор** — кольцо выполнения, сколько задач отправлено, в работе сейчас, среднее время, график по дням,
  «дольше всего в работе», разбивка по важности и по типу сообщений, последние задачи.
- **Прорабы** — карточка каждого: сколько задач, процент выполнения, статусы, важность и **как отправлено**
  (текст / фото / голосовое / видео / файл); переход к задачам прораба одним нажатием.
- **Задачи** — лента всех задач с фильтрами по статусу и прорабу и подгрузкой по мере прокрутки; на ПК это таблица
  с выровненными колонками «Прораб · Задача · Результат», на телефоне — карточки.
  **Фото** показываются превью (несколько — сеткой, в таблице на ПК — значком «🖼 N») и открываются на весь экран
  с листанием (стрелки, `←`/`→`, свайп; тап — увеличить), **голосовые** воспроизводятся
  прямо в карточке: перемотка по «волне», скорость 1× / 1.5× / 2×.

Видео и файлы в карточке помечены значком — их по-прежнему открывают в боте.

### Страница задачи

Нажмите на любую задачу (карточку или строку) — откроется её отдельная панель: на ПК выезжает справа (список остаётся
виден), на телефоне открывается на весь экран, назад — системной кнопкой Telegram или `Esc`. В панели:

- статус, важность, тип вложений и прораб (со ссылкой «Все задачи» — открывает ленту только по нему);
- **полное описание** целиком и с переносами строк (в списках оно сокращено);
- **все фото** крупно (нажатие — просмотр с листанием), голосовое с плеером, пометка о видео и файлах;
- **хронология**: когда отправлена, когда и как закрыта, за сколько; у задачи в работе — «уже N ч/дн»;
- кнопки результата внизу — всегда под рукой, как бы длинным ни было описание.

Кнопки, плеер и фото внутри карточки открывают своё, а не панель; выделение текста клик по карточке тоже не срабатывает.

### Отметка результата из дашборда

У каждой задачи «в работе» есть кнопки **✅ Выполнено**, **❌ Не выполнено** и **🚫** (отменить — если задача отправлена по ошибке).
Правила те же, что у кнопок в боте: решение принимает шеф, прорабу ничего не отправляется. Статус и цифры на «Обзоре» и
«Прорабах» обновляются сразу.

- После нажатия внизу появляется уведомление с кнопкой **«Вернуть в работу»** — так исправляется случайный клик
  (то же есть в карточке закрытой задачи).
- Под фильтром «В работе» закрытая задача сразу уходит из списка, а «Вернуть» возвращает её на место.
- Если задачу уже закрыли в другом месте (например, в боте), дашборд покажет актуальный статус и сообщит об этом.

### Телефон, планшет, ноутбук и ПК

Интерфейс сам подстраивается под ширину окна (в Telegram Desktop окно можно растягивать, а на macOS и Windows —
развернуть кнопкой «⤢ На весь экран» в боковой панели):

| Ширина        | Раскладка                                                                                          |
| ------------- | -------------------------------------------------------------------------------------------------- |
| до 900 px     | телефон / планшет: нижняя панель вкладок, одна колонка, прорабы карточками                         |
| от 900 px     | ноутбук / ПК: боковая навигация, широкий «обзор» в две колонки, **таблица прорабов**, **таблица задач** (кнопки результата — отдельной колонкой справа, а на узком окне — строкой под текстом) |

На ПК дополнительно: сортировка таблицы по любой колонке (клик по заголовку) и строка «Итого», клик по прорабу
открывает его задачи, подсказка на графике при наведении мыши, просмотр фото по `Esc`/клику, горячие клавиши
**1 / 2 / 3** — разделы, **R** — обновить.

### Подключение

Telegram открывает Mini App только по **HTTPS**, поэтому нужен публичный адрес.

```bash
# 1. собрать интерфейс (один раз и после каждого изменения webapp/)
cd webapp && npm ci && npm run build && cd ..

# 2. в .env указать адрес, по которому снаружи виден порт WEB_PORT
WEBAPP_URL=https://dash.example.com

# 3. запустить бота как обычно — он же раздаёт и API, и интерфейс
python -m bot.main
```

HTTPS на сервере — любой reverse proxy, например Caddy (сертификат выпускается сам):

```
dash.example.com {
    reverse_proxy 127.0.0.1:8080
}
```

Для проверки без своего домена подойдёт временный туннель: `cloudflared tunnel --url http://localhost:8080` —
выданный `https://….trycloudflare.com` впишите в `WEBAPP_URL`.

После запуска у шефа появляется кнопка **«📊 Дашборд»** рядом с полем ввода, команда `/dashboard`
и кнопка «📱 Открыть дашборд» под статистикой.

### Фото и голосовые

Telegram отдаёт файлы только через Bot API, поэтому сервер скачивает файл один раз и кэширует на диске
(`MEDIA_CACHE_DIR`, по умолчанию `data/media`, лимит `MEDIA_CACHE_MB` — самые старые файлы вытесняются).
Для превью в ленте используется размер фото ≈800 px, оригинал подгружается при открытии на весь экран.

Голосовые в Telegram — OGG/Opus. Android и десктоп играют их сами, а **iOS-WebView — нет**: для него сервер
перекодирует голос в M4A через `ffmpeg` (кэшируется). Поэтому на сервере желательно поставить ffmpeg:

```bash
sudo apt install ffmpeg        # Arch: sudo pacman -S ffmpeg
```

Без ffmpeg всё остальное работает, но на iPhone голосовые в дашборде не воспроизведутся.
Ограничение Bot API: файлы больше 20 МБ скачать нельзя (для фото и голосовых это не бывает).
Задачи, созданные до этого обновления, показываются так же, только без отдельного превью (грузится полный размер)
и без длительности в заголовке плеера (она появляется после загрузки).

### Безопасность

- Каждый запрос подписан Telegram (`initData`, HMAC-SHA256 от токена бота, срок жизни 24 часа) и проверяется на сервере.
- Доступ только у пользователей с ролью шефа; каждый шеф видит **только своих** прорабов и задачи.
- Ссылки на фото и голосовые подписаны (HMAC) и действуют 6–12 часов; выдаются только вместе с данными шефа,
  подобрать или подделать ссылку на чужую задачу нельзя.
- Изменить из дашборда можно только статус **своей** задачи (`POST /api/tasks/{id}/status`); чужие задачи для шефа «не найдены».
  Запрос защищён той же подписью Telegram, куки не используются, поэтому подделать запрос с другого сайта нельзя.

## Как это работает

### Отправка задачи (шеф)

1. «➕ Новая задача».
2. Отправьте боту задачу — **текстом, фото или голосовым** (к фото можно добавить подпись). **Несколько фото** можно
   отправить одним альбомом, переслать или присылать по одному, пока бот спрашивает важность: всё соберётся
   в **одну задачу** (до 10 штук; счётчик «Принято — 📷 Фото: 3» обновляется в том же сообщении).
3. Выберите **важность** — от неё зависит срок выполнения (он указан прямо на кнопках):
   🟢 обычная — 1 месяц · 🟡 важная — 7 дней · 🔴 срочная — 1 день. Срок виден прорабу в задаче, а шефу — в боте и дашборде
   (просроченная задача в работе подсвечивается).

**Кнопка «👍 Принял» у прораба.** Под каждой новой задачей у прораба две кнопки: «Принял» и «Сделал». После «Принял» шефу приходит
короткое уведомление, а в дашборде у задачи появляется отметка «👍 принял» (до этого — «👀 не принял») и шаг в хронологии
с временем. В списке прораба непринятые задачи помечены 🆕. Если прораб сразу нажал «Сделал», задача считается принятой.

**Кнопка «✅ Сделал» и фото результата.** Когда прораб закончил, он нажимает «Сделал» под задачей, и бот просит прислать
**фото того, что сделано** (до 10 штук). Описание — подписью к фото или отдельным сообщением; можно отправить и без фото
(«⏭ Без фото»). Пока прораб не нажал «📤 Отправить шефу», задача остаётся в работе — ничего не теряется, если он передумал
(«✖️ Отмена») или отвлёкся.

После отправки задача получает статус ☑️ «ждёт одобрения» и уходит из списка прораба. Шефу в чат приходит **отчёт: фото
с описанием** и кнопки «✅ Одобрить», «↩️ Вернуть в работу», «❌ Не выполнено». В дашборде фото и описание лежат в карточке
«Подробнее о задаче» (блок «📸 Отчёт прораба»; если задачу возвращали в работу, там все отчёты по порядку), а в списках у такой
задачи есть пометка «📸 фото результата». Для задач, ждущих одобрения, есть блок на «Обзоре», фильтр «☑️ Ждут одобрения»
и плитка со счётчиком. В статистику «выполнено» задача попадает только после одобрения шефом.
4. Выберите прорабов (одного или нескольких) и нажмите «📤 Отправить выбранным» — или сразу «👥 Отправить всем».

Каждому прорабу создаётся своя задача, чтобы по ним считалась отдельная статистика.
Сообщение приходит прорабу в том же виде (фото остаётся фото, голосовое — голосовым) с заголовком «Новая задача · важность».
Задача с несколькими фото приходит прорабу **одним альбомом** (заголовок и подпись — у первого фото). Фото и видео
можно смешивать в одном альбоме. Дополнительно принимаются одиночные видео и файлы.

В дашборде такая задача показывается сеткой фото (как в Telegram), по нажатию открывается просмотр с листанием.
Видео из альбома в дашборде не воспроизводятся — на карточке стоит пометка «🎥 Видео ×N», открывать их нужно в боте.

### Панель прораба

- Задачи копятся у прораба: «📋 Мои задачи» — список задач в работе (срочные сверху), нажатие открывает задачу.
- «📈 Моя статистика» — сколько задач получено, выполнено, не выполнено и в работе, процент выполнения,
среднее время и последние задачи.
- Прорабу ничего подтверждать не нужно — он только получает задачи.

### Отметка результата (шеф)

«📋 Активные задачи» → нажать на задачу → **✅ Выполнено / ❌ Не выполнено** (или 🚫 Отменить, если отправили по ошибке).
Статистика прораба обновляется сразу.

Статусы: `🔧 В работе` → `✅ Выполнена` / `❌ Не выполнена` / `🚫 Отменена`.

### Роли

- **Шеф** — из `ADMIN_IDS` (можно несколько, у каждого свои прорабы). Видит и меняет только свои задачи.
- **Прораб** — регистрируется по ссылке-приглашению шефа и после его подтверждения. Видит только свои задачи.

### Статистика (шеф: 📊, прораб: 📈)

| Показатель        | Как считается                          |
| ----------------- | -------------------------------------- |
| Всего / ✅ / ❌ / 🔧 | количество задач по статусам           |
| Выполнение        | выполнено ÷ (выполнено + не выполнено) |
| Среднее время     | от отправки до отметки «выполнено»     |

У шефа: период 7 / 30 дней / всё время, сводка по каждому прорабу и итог по участку,
карточка прораба (разбивка по важности, последние 10 задач), экспорт CSV для Excel.
То же самое, но подробнее и с графиками — в дашборде.

### Автоматика

Одна: утром в `DIGEST_HOUR` приходят сводки (если показывать нечего — не приходят):
- шефу — сколько задач в работе у каждого прораба, сколько ждёт его одобрения и сколько не принято;
- каждому прорабу — его собственная сводка: задачи в работе по важности, сроки (просроченные с 🔥), непринятые (👀),
  сколько ждёт одобрения шефа. Прорабам без задач ничего не отправляется. Не нужна — уберите `_digest` в `bot/scheduler.py`.

## Переход с SQLite на PostgreSQL

Если бот уже работал на SQLite, перенесите данные одной командой (можно запускать повторно — дубликатов не будет):

```bash
python -m scripts.migrate_sqlite_to_pg data/bot.db      # DATABASE_URL берётся из .env
```

Переносятся шефы, прорабы, задачи (с теми же номерами `#id`) и служебные отметки. Задачи самой первой версии
(с названием и сроком, таблица `tasks_legacy`) в статистику не входили и не переносятся.
После проверки файл `data/bot.db` можно архивировать — он в `.gitignore`.

## Структура проекта

```
bot/
  main.py        запуск: PostgreSQL → бот → планировщик → веб-сервер дашборда
  config.py      настройки из .env
  db.py          PostgreSQL (asyncpg): схема, запросы, статистика, кэш ролей
  scheduler.py   утренняя сводка шефу
  texts.py       заголовки задач и блоки статистики
  keyboards.py   все кнопки
  states.py      шаги диалога (содержимое → важность → прорабы)
  filters.py     проверка роли (шеф / активный прораб)
  notify.py      безопасная отправка (текст, фото, голосовое) и редактирование
  utils.py       время (TIMESTAMPTZ в базе, локальное в интерфейсе)
  handlers/      common (/start, /help), chief, foreman, fallback
  web/
    auth.py      проверка подписи Telegram initData
    media.py     фото и голосовые: подписанные ссылки, дисковый кэш, перекодирование в M4A
    server.py    JSON API (/api/dashboard, /api/tasks, /api/tasks/{id}, POST /api/tasks/{id}/status, /api/media/…) + раздача собранного React
webapp/          дашборд: React + Vite
  src/components/  Hero, Overview, Team, TasksTab, TaskCard/TaskRow, TaskPanel (страница задачи), VoicePlayer, Media (фото + просмотрщик), график…
scripts/migrate_sqlite_to_pg.py
tests/           smoke_test.py, handlers_test.py, media_test.py, actions_test.py
docker-compose.yml   PostgreSQL для разработки
```

Таблицы: `users` (шефы и прорабы), `tasks` (вид, file_id, превью фото, длительность голосового, текст, важность, статус, время отправки и закрытия), `meta` (служебное).
Новые колонки добавляются при запуске автоматически (`ADD COLUMN IF NOT EXISTS`) — существующую базу трогать не нужно.
Даты — `TIMESTAMPTZ`, показываются в часовом поясе `TZ` (по умолчанию `Asia/Dushanbe`). Telegram ID — `BIGINT`.

## Быстродействие

- **Пул соединений** asyncpg вместо одного соединения: запросы бота и дашборда идут параллельно.
- **Индексы** под реальные выборки: `(chief_id, created_at)`, `(foreman_id, created_at)` для периодов и частичные
  индексы только по задачам «в работе» — списки активных задач не зависят от размера истории.
- **Статистика за один проход**: статусы, важность и типы сообщений считаются одним `GROUP BY … FILTER`,
  без коррелированных подзапросов (раньше счётчик «в работе» считался подзапросом на каждого прораба).
- **Кэш ролей** (60 с, сбрасывается при любом изменении пользователя): фильтры `IsChief` / `IsActiveForeman`
  больше не ходят в базу на каждое сообщение и каждое нажатие кнопки.
- **Рассылка задачи**: одна вставка на всех выбранных прорабов и параллельная отправка (до 10 одновременно)
  вместо цикла «создать → прочитать → отправить» по одному.
- Выбор прорабов в диалоге не обращается к базе при каждом нажатии галочки; карточка прораба и «Моя статистика»
  выполняют свои запросы параллельно.
- Утренняя сводка — один запрос на всех шефов, планировщик просыпается раз в 5 минут вместо раза в минуту.
- Бот запрашивает у Telegram только те типы обновлений, которые обрабатывает (`allowed_updates`).
- Лента задач: постраничная выборка по `id` (keyset) — не замедляется на глубоких страницах; фото грузятся лениво,
  браузер кэширует их на сутки, сервер — на диске.
- Дашборд: один HTTP-запрос на экран, параллельные SQL-запросы, серверный кэш на 5 секунд, сжатые статические
  файлы (≈50 КБ JS), мгновенное переключение периодов (данные кэшируются в приложении и обновляются в фоне).

## Запуск на сервере

Простой вариант — systemd (`/etc/systemd/system/foreman-bot.service`):

```
[Service]
WorkingDirectory=/opt/foreman-bot
EnvironmentFile=/opt/foreman-bot/.env
ExecStart=/opt/foreman-bot/.venv/bin/python -m bot.main
Restart=always
User=bot

[Install]
WantedBy=multi-user.target
```

Резервная копия — `pg_dump foreman > backup.sql` (например, по cron раз в сутки).

## Ограничения и что можно добавить дальше

- В одной задаче — не больше 10 фото/видео (лимит Telegram на альбом); остальные игнорируются.
- Диалоги (создание задачи) хранятся в памяти: при перезапуске бота незавершённое создание сбрасывается.
Сами задачи в базе не теряются. Для продакшена с частыми перезапусками подключите `RedisStorage`.
- Идеи для развития: ответ прораба фото-отчётом, повторяющиеся задачи, шаблоны задач, группы прорабов;
в дашборде — просмотр видео, комментарий к результату.
